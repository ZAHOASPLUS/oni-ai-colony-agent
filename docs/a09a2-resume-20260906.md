## Required core behavior

1. Every public mutating API acquires/reuses the actual lifecycle OS lock and
   runs strict recovery/duplicate checks itself. A cooperative caller lock is
   not a precondition that the public API may silently assume.
2. Direct pending publication validates canonical id/filename/stage/status
   and checks every protected stage under the lock. It must not overwrite or
   create another visible copy of an id. Content validation is not policy or
   approval authority.
3. Keep a persistent lock inode: never break a supposedly stale lock by deleting
   its pathname. Crashed OS handles release naturally. Validate identities on
   reentry; support bounded thread recursion and finite timeout. Reject unsafe
   ancestors before creating directories. Test actual process exclusion.
4. Journal recovery validates an exact schema/keyset, bounded strings, id,
   stage/status and canonical source/destination role mapping. Temporary payload
   paths must be transaction-owned, under the exact expected stage/directory,
   and tied to journal identity. Unknown, malformed, unreadable or duplicated
   journals cannot be skipped or merely returned as a nonblocking label.
5. Recovery must never adopt approved/executing/confirming/done records as
   source or temporary material, even when a tampered journal self-hash agrees.
   Reparse points, junctions, hardlinks, aliases and moved directories are
   rejected. Do not follow an unsafe path in diagnostics or cleanup.
6. Cleanup requires recorded file identity and expected exact content/hash,
   not only regular-file kind and link count. Another actor's replaced file
   must survive, with uncertainty latched. Treat orphan payloads as evidence,
   not invisible litter or automatically deletable files.
7. At every injected failure boundary preserve exactly one original owner,
   exactly one verified terminal owner, or an explicitly blocking unknown
   outcome with evidence. Never report success after swallowing an exception.
   A published destination must not coexist with a replayable source.
8. No generic os.replace over a protected command. The module provides
   integrity relative to its trusted local owner, not authentication against
   an administrator who can replace every root and process.
