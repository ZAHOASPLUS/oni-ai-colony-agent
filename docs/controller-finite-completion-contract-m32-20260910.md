# ONI 控制器有限完成契约（M32）

日期：2026-09-10 CST。状态：目标与验收设计已明确，尚未实现或通过运行验收。

用户要求完整 ONI 控制器，并在终局目标询问后回复“网络自行检索”。本契约据此采用官方主要目标作为通关依据，不再要求用户凭记忆提供成就清单。整体 Goal 不变；M28 单次优先级动作只是实现里程碑。

## 1. 通关目标的来源与选择

Klei 官方将 Imperatives 定义为殖民地的主要目标，将 Initiatives 定义为可选目标和检查点。[S1] 因此，本项目正式游戏终局是：**完成绑定版本、DLC 和所选克隆场景实际适用的全部官方 Imperatives**，并满足下述控制器、工业、生存、学习和安全收尾验收。

当前官方 Steam 成就页可以核实以下五个主要目标的名称与对应关系。[S2]

| 官方成就 | 官方主要目标 | 当前应如何绑定 |
|---|---|---|
| Home Sweet Home | Colonize Imperative | 纳入当前构建的殖民主要目标；保存该场景完整条件集合及逐项完成证据 |
| The Great Escape | Escape Imperative | 纳入当前构建的逃离主要目标；记录目标事件及复制人身份，不能用普通火箭计数替代 |
| Cosmic Archaeology | Exploration Imperative | 按实际 DLC、游戏目标列表和世界内容确认适用性及完整子条件 |
| Blast Line of Defense | Defense Imperative | 需核实场景中的 Demolior 内容和正式目标定义；不能仅根据拥有 Prehistoric DLC 推断 |
| Full Steam Ahead | Power Imperative | 需核实 Frosty/Ceres 场景及正式目标定义；不能给所有存档强加此目标 |

Klei 的 Prehistoric 发布说明明确指出：旧档升级 DLC 不会补生成 Demolior。[S3] Frosty 发布说明也指出新世界生成内容不能补入旧档，[S4] 且官方热修复曾纠正非 Ceres 场景错误显示 Full Steam Ahead 的问题。[S5] 因此，“拥有 DLC”“网页存在成就”“场景实际适用”是三种不同证据。

将实际适用集合记为 `I`。集合必须非空、完整，并绑定游戏程序集、有效 DLC 和场景身份；未知适用性阻止验收。某个适用目标难以完成、缺少控制器能力或历史上已经失败，不是从 `I` 删除它的理由。只有该版本/场景正式不适用，才能有证据地排除。

2019 年社区资料列出 Home Sweet Home 的 200 周期、16 morale、12 duplicants、Great Monument，以及 Escape 的 Temporal Tear 条件。[S7] 这些是后续核对线索，不能直接当作 cl-744825 的完整数值规则。Exploration、Defense、Power 的完整当前子条件本次未取得足够可靠的逐项数值资料；实施前须从绑定构建的只读定义或正式游戏观察补录，禁止猜测数量。

## 3. 六个前进阶段与恢复行为

以下是目标行为设计，不是现有五阶段代码已经实现的声明。所有阶段都要有真实 observation → state → objective → plan → bounded action → later observation → reconciliation 链路、有限动作/观察预算及对应测试。信任失败进入恢复，未知结果不重发。

| 阶段 | 进入条件 | 完成条件 | 回退 |
|---|---|---|---|
| 早期生存 | 精确克隆已准入，身份、可达性与安全观测有效 | 氧气、可食用且可达食物、卫生及立即人身安全已稳定；完成至少一个实际有效的控制动作 | 最早未满足的生存目标；缺可信观测则停止动作 |
| 稳定殖民地 | 生存条件成立 | 水、电、压力/士气、研究与运送能维持现有人口；目标不只停留在推荐文本 | 出现资源/健康风险时回到生存 |
| 扩张 | 稳定基地有量化储备和余量 | 必需区域及适用世界可安全访问，输送与生命支持覆盖新增需求 | 冻结扩张；先修复最早失效的基地条件 |
| 工业 | 扩张所需安全与供给成立 | 为集合 `I` 和可持续基地需要的有限配方/物料清单，完成实际生产、交付、热管理及废物处理；不能以蓝图或建筑数量替代产出 | 停止新增工业负载，保护生命支持并恢复生产链 |
| 航天及官方终局 | 工业、燃料、装备、任务与基地储备就绪 | `I` 中所有适用目标及其完整子条件有游戏内完成记录；任务事件、复制人身份、货物/目标结果可核对 | 普通任务不能证明返航与基地安全时不得派遣；失败按已知状态恢复，不重复不明动作 |
| 可持续完成 | 官方主要目标完成，基地各关键系统仍运行 | 满足第 4 节有限压力与供给周期验收，保持控制能力及所有必要资源约束 | 任一关键系统失效则撤销完成候选，回到最早失效阶段 |

恢复不是第七个前进目标。恢复退出只证明重新获得可信观察，不会自动证明先前阶段已完成。

官方逃离终局不能被错误建模成“所有任务都必须返回”。社区资料描述 Temporal Tear 为不返航终局。[S8] 在当前构建证实这一行为前不派遣；实施时必须区分官方成功逃离、仍在执行的任务、正常返航、失踪和死亡。禁止将失踪/死亡伪装成逃离，也不能为了适配通关条件而降低其他人身安全约束。

## 4. 有限的工业与可持续验收

本节是本项目的工程验收设计，不是 Klei 官方成就条件，也不声称从有限运行证明数学意义的永远生存。

在运行前冻结有限的关键消费者、关键区域、资源来源、依赖关系、目标配方/交付清单和单一故障集合。范围包含全部实际有人口的世界及相互依赖的运输路径，不能用一个活跃世界的部分视野代表整个殖民地。

对氧气、食物、水和电分别核对：可用库存与可达性、实际产出、实际消耗、运输/转换损耗、最大无供给间隔及最长恢复时间。储备至少覆盖相应间隔内需求和恢复期间需求；完整供给周期内净产出不能低于需求与损耗。没有定量语义、单位、范围及新鲜来源的数据不得满足条件。热管理、卫生、士气和复制人安全也必须在同一窗口内有效。

令 `P` 为真正依赖的间歇性再生来源中最长的完整供给周期（包括休眠）；连续来源可按 1 周期处理。最终观测长度 `H=max(10,P)` 个实际游戏周期。当前代码的 10 周期值只是最低窗口，不能用它掩盖尚未覆盖的较长休眠周期。`P` 未知则窗口未定义，验收阻止；暂停时间和突发离线回放不能累积有效游戏周期。

还须对冻结的每个单一关键依赖故障证明：替代供给与储备可维持关键需求直到恢复。证据可以来自受控、获准的克隆故障试验及与实际观测绑定的依赖分析，不能仅凭“两台建筑”认定独立。任何试验仍服从既有准入与动作权限；本契约不授予故障注入权限。

工业验收必须证明目标配方实际完成、产物交付、输入供给与热/废物处理可持续。物料总量来自冻结的官方目标和基地需求清单，不无限扩大为任意囤积目标，也不能删掉难以实现的必要物料。

完成候选由上述实际证据和窗口计算输出。当前 `strategy.py:2607` 还要求输入 `colony.sustainable=true`，而 Probe 在 `SurvivalTelemetryReader.cs:1212` 明确输出 null/unsupported；该现有路径必须修复。不能直接翻转标志或伪造可信证明来满足本契约。

## 5. 学习与改进的有限验收

至少完成一次可复现的完整学习闭环：实际游戏记录 → 隔离候选策略/规则 → 固定回放与留出集 → 获准测试克隆 → 实测改进 → 精确版本提升或回滚。先冻结评价指标、对照版本、数据分割和预算，再运行；不能看到结果后改变通过标准。

同一 `clone_lineage`、会话及相邻证据窗口不得跨训练和留出集泄漏。修复当前学习草案 `clone_lineage` 与 `save_lineage` 的命名不一致。提升须在与真实目标相关的预先选定指标上优于基线，并且无新增 false-ready、无未解释的安全退化、无权限越界；仅比基线更快计算不等于更会玩 ONI。没有真实克隆结果，不得声称策略提升已通过端到端验收。

## 6. 其他成就及最终收尾

Initiatives 和挑战成就另列有限资格表：已完成、仍可达、历史条件失效、正式不适用、证据不足。官方当前 Carnivore 含第 100 周期前的截止条件，Locavore 与 Super Sustainable 含历史行为限制。[S2] 因此不能对任意现有存档承诺所有挑战均可补齐。不得重写存档、重置失败状态或关闭安全要求来制造成就。用户以后若选择额外挑战，应明确增加到所选目标集合。

整体 Goal 完成时必须同时证明：

1. 所选输入和 `I` 已精确绑定；全部适用官方主要目标及完整子条件通过。
2. 六阶段可执行控制与真实动作效果得到验证，主要行为领域的能力清单逐项有证据。
3. 工业、资源、热、卫生、人员、运输和故障恢复通过有限窗口验收。
4. 至少一个完整、实测有效的学习与提升/回滚闭环通过。
5. 运行正常退出，原存档/预览哈希保持原值，正常 Mod/config 恢复，命令队列为空，无遗留运行帮助进程。

当前没有任何一组整体完成证据。M29 仍为 configured_not_restored、无 plan 的 recovery latch；不得重跑旧 Apply 或删除 stage/latch。M28 Build 3→4 实现仍待可用的 Luna Max/Spark 作者；本次文档工作未改变路由授权。
